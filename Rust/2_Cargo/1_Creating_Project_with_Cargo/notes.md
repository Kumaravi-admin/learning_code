# The Rust Programming Language

## Hello, Cargo!

Cargo Rust ka build system aur package manager hai. Zyadatar Rustaceans is tool ka use apne Rust projects ko manage karne ke liye karte hain kyunki Cargo aapke liye kaafi saare tasks handle karta hai, jaise aapke code ko build karna, aapke code ko chalane ke liye jo libraries chahiye unhe download karna, aur un libraries ko build karna. _(Jo libraries aapke code ko chahiye hoti hain, unhein hum **dependencies** kehte hain.)_

Sabse simple Rust programs, jaisa ki humne abhi tak likha hai, mein koi dependencies nahi hoti hain. Agar humne “Hello, world!” project ko Cargo ke sath banaya hota, toh yeh Cargo ke sirf us part ka use karta jo aapke code ko build karne ka kaam karta hai. Jaise-jaise aap aur complex Rust programs likhenge, aap dependencies add karenge, aur agar aap Cargo ka use karke koi project shuru karte hain, toh dependencies add karna kaafi aasaan ho jayega.

Kyunki vast majority of Rust projects Cargo ka use karte hain, is book ka baaki hissa yeh manta hai ki aap bhi Cargo ka use kar rahe hain. Cargo, Rust ke sath pre-installed aata hai agar aapne official installers ka use kiya hai jo “Installation” section mein discuss kiye gaye hain. Agar aapne Rust kisi aur tareeqe se install kiya hai, toh check karein ki Cargo installed hai ya nahi, apne terminal mein yeh enter karke:

```bash
cargo --version
```

Agar aapko ek version number dikhe, toh aapke paas yeh hai! Agar aapko koi error dikhe, jaise `command not found`, toh apne installation ke method ki documentation dekhein taaki yeh pata chal sake ki Cargo ko alag se kaise install karna hai.

### Creating a Project with Cargo

Chaliye Cargo ka use karke ek naya project banate hain aur dekhte hain ki yeh hamare original “Hello, world!” project se kaise alag hai. Apne projects directory (ya jahan bhi aapne apna code store karna decide kiya hai) par wapas jayein. Phir, kisi bhi operating system par, yeh run karein:

```bash
cargo new hello_cargo
cd hello_cargo
```

Pehla command ek naya directory aur project banata hai jiska naam `hello_cargo` hai. Humne apne project ka naam `hello_cargo` rakha hai, aur Cargo iske files ko same naam ke ek directory mein banata hai.

`hello_cargo` directory ke andar jayein aur files ko list karein. Aap dekhenge ki Cargo ne hamare liye do files aur ek directory generate ki hai: ek `Cargo.toml` file aur ek `src` directory jiske andar ek `main.rs` file hai.

Isne ek naya Git repository bhi initialize kiya hai, sath hi ek `.gitignore` file bhi. Agar aap kisi existing Git repository ke andar `cargo new` run karte hain, toh Git files generate nahi hongi; aap `cargo new --vcs=git` ka use karke is behavior ko override kar sakte hain.

> **Note:** Git ek common version control system hai. Aap `cargo new` ko change karke kisi doosre version control system ya bina kisi version control system ke `--vcs` flag ka use karke set kar sakte hain. Available options dekhne ke liye `cargo new --help` run karein.

Apne pasand ke text editor mein `Cargo.toml` open karein. Yeh Listing 1-2 ke code jaisa dikhna chahiye.

**Filename: `Cargo.toml`**

```toml
[package]
name = "hello_cargo"
version = "0.1.0"
edition = "2024"

[dependencies]
```

_Listing 1-2: Contents of Cargo.toml generated by cargo new_

Yeh file **TOML** (_Tom’s Obvious, Minimal Language_) format mein hai, jo ki Cargo ka configuration format hai.

- Pehli line, `[package]`, ek section heading hai jo yeh batati hai ki aage ke statements ek package ko configure kar rahe hain. Jaise-jaise hum is file mein aur information add karenge, hum doosre sections bhi add karenge.
- Agle teen lines wo configuration information set karte hain jo Cargo ko aapke program ko compile karne ke liye chahiye: **naam**, **version**, aur use karne ke liye **Rust ka edition**. Hum edition key ke baare mein Appendix E mein baat karenge.
- Aakhri line, `[dependencies]`, ek aise section ki shuruat hai jahan aap apne project ki koi bhi dependencies list kar sakte hain. Rust mein, code ke packages ko **crates** kaha jata hai. Hamein is project ke liye kisi aur crate ki zaroorat nahi hai, lekin Chapter 2 ke pehle project mein hume zaroorat padegi, toh hum tab is dependencies section ka use karenge.

Ab `src/main.rs` open karein aur dekhein:

**Filename: `src/main.rs`**

```rust
fn main() {
    println!("Hello, world!");
}
```

Cargo ne aapke liye ek “Hello, world!” program generate kiya hai, bilkul waisa hi jaisa humne Listing 1-1 mein likha tha! Abhi tak, hamare project aur Cargo dwara generate kiye gaye project mein fark yeh hai ki Cargo ne code ko `src` directory mein rakha hai, aur top directory mein hamare paas ek `Cargo.toml` configuration file hai.

Cargo yeh ummeed karta hai ki aapke source files `src` directory ke andar hi rahein. Top-level project directory sirf README files, license information, configuration files, aur aisi hi doosri cheezon ke liye hai jo aapke code se related nahi hain. Cargo ka use karne se aapke projects ko organize karne mein madad milti hai. Har cheez ke liye ek jagah hoti hai, aur har cheez apni jagah par hoti hai.

Agar aapne ek aisa project shuru kiya hai jo Cargo ka use nahi karta, jaisa ki humne “Hello, world!” project ke sath kiya tha, toh aap ise ek aise project mein convert kar sakte hain jo Cargo ka use karta hai. Project code ko `src` directory mein move karein aur ek appropriate `Cargo.toml` file banayein. Us `Cargo.toml` file ko paane ka ek aasaan tarika `cargo init` run karna hai, jo aapke liye ise automatically bana dega.

### Building and Running a Cargo Project

Ab dekhte hain ki jab hum Cargo ke sath “Hello, world!” program ko build aur run karte hain toh kya alag hota hai! Apne `hello_cargo` directory se, niche diye gaye command ko enter karke apne project ko build karein:

```bash
cargo build
```

**Output:**

```text
Compiling hello_cargo v0.1.0 (file:///projects/hello_cargo)
Finished dev [unoptimized + debuginfo] target(s) in 2.85 secs
```

Yeh command aapke current directory ki bajaye `target/debug/hello_cargo` (ya Windows par `target\debug\hello_cargo.exe`) mein ek executable file banata hai. Kyunki default build ek debug build hai, Cargo binary ko `debug` naam ke ek directory mein rakhta hai. Aap is command se executable ko run kar sakte hain:

```bash
./target/debug/hello_cargo # ya Windows par .\target\debug\hello_cargo.exe
```

**Output:**

```text
Hello, world!
```

Agar sab kuch theek raha, toh terminal mein `Hello, world!` print ho jana chahiye. Pehli baar `cargo build` run karne par Cargo top level par ek naya file bhi banata hai: `Cargo.lock`. Yeh file aapke project mein dependencies ke exact versions ka track rakhti hai. Is project mein dependencies nahi hain, isliye yeh file thodi si khaali (sparse) hai. Aapko kabhi bhi is file ko manually change karne ki zaroorat nahi padegi; Cargo iske contents ko khud manage karta hai.

Humne abhi `cargo build` ke sath ek project banaya aur ise `./target/debug/hello_cargo` ke sath run kiya, lekin hum ek hi command mein code ko compile aur phir resultant executable ko run karne ke liye `cargo run` ka bhi use kar sakte hain:

```bash
cargo run
```

**Output:**

```text
Finished dev [unoptimized + debuginfo] target(s) in 0.0 secs
Running `target/debug/hello_cargo`
Hello, world!
```

`cargo run` ka use karna is baat ko yaad rakhne se zyada convenient hai ki pehle `cargo build` run karna hai aur phir binary ka poora path use karna hai, isliye zyadatar developers `cargo run` ka use karte hain.

Dhyan dein ki is baar humne aisi koi output nahi dekhi jo yeh bataye ki Cargo `hello_cargo` ko compile kar raha hai. Cargo ne yeh pata laga liya ki files change nahi hui hain, isliye isne dobara build nahi kiya balki seedha binary ko run kar diya. Agar aapne apna source code modify kiya hota, toh Cargo run karne se pehle project ko dobara build karta, aur aapko yeh output dikhti:

```bash
cargo run
```

**Output:**

```text
Compiling hello_cargo v0.1.0 (file:///projects/hello_cargo)
Finished dev [unoptimized + debuginfo] target(s) in 0.33 secs
Running `target/debug/hello_cargo`
Hello, world!
```

Cargo ek aur command bhi provide karta hai jise `cargo check` kehte hain. Yeh command aapke code ko jaldi se check karta hai yeh ensure karne ke liye ki yeh compile hota hai lekin koi executable produce nahi karta:

```bash
cargo check
```

**Output:**

```text
Checking hello_cargo v0.1.0 (file:///projects/hello_cargo)
Finished dev [unoptimized + debuginfo] target(s) in 0.32 secs
```

### Summary (Cargo Recap)

Abhi tak humne Cargo ke baare mein jo seekha hai, uska recap:

- Hum `cargo new` ka use karke ek project bana sakte hain.
- Hum `cargo build` ka use karke ek project build kar sakte hain.
- Hum `cargo run` ka use karke ek hi step mein project ko build aur run kar sakte hain.
- Hum `cargo check` ka use karke bina binary banaye project ko errors ke liye check kar sakte hain.
- Build ka result same directory mein save karne ki bajaye, Cargo ise `target/debug` directory mein store karta hai.
